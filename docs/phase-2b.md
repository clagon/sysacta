# Sysacta — Phase 2B: ネットワーク管理

## 目的・範囲

spec §7.7 / §8 / §10 / §11 に従い、Windows のネットワーク接続状態・アダプター一覧・通信カウンター/速度・限定したアダプター管理状態の変更を提供する。

最初に AGENTS.md、README.md、docs/spec.md、docs/tools.md、docs/security.md、docs/manual-tests.md、docs/phase-1a-progress.md、docs/phase-1e-progress.md、docs/phase-1f-progress.md、docs/phase-2a-progress.md と既存の実装・テストを読む。最新 main から専用ブランチ（例: phase-2b）を作る。

本フェーズの最重要事項は、リモート MCP の接続喪失を防ぐこと、誤ったインターフェースへの操作を防ぐこと、通信速度を正しく測定することである。安全に実装できない変更機能・環境・対象は未対応として扱う。読み取りを先に完成させ、変更操作は独立したコミットで検証する。Phase 2C 以降、Phase 1/2A の残課題、汎用ネットワーク管理機能には着手しない。

対象外: Wi-Fi 接続先/資格情報の設定、IP/DHCP/DNS/ゲートウェイ/ルーティング/メトリック/FW/VPN/プロキシ設定変更、ネットワーク探索・ポートスキャン・ping 等の外部ホストへの通信、パケットキャプチャ、プロセス別通信監視、任意 WMI/PowerShell/netsh/シェル実行、ドライバー管理/デバイスの削除、再接続の自動化、永続監視・ダッシュボード。

## 1. 技術調査

Microsoft の公式文書、Windows SDK、.NET 10 の仕様を確認し、docs/phase-2b-progress.md に API の採否、参照 URL、対象 OS・権限・型/単位、失敗時の契約、依存/ライセンスを記録する。

| 用途 | 調査候補 |
|---|---|
| アダプター・管理/稼働状態、リンク速度 | IP Helper GetIfTable2 / GetIfEntry2、MIB_IF_ROW2、FreeMibTable |
| IP アドレスとプレフィックス | GetAdaptersAddresses、または NetworkInterface / IPInterfaceProperties |
| 安定 ID と実行時照合 | InterfaceGuid / NET_LUID / InterfaceIndex、ConvertInterfaceGuidToLuid 等 |
| 送受信カウンター | MIB_IF_ROW2 の 64 bit InOctets / OutOctets 等 |
| 現在の経路・依存関係 | GetIpForwardTable2 / GetBestRoute2、インターフェースとアドレス、GetIfStackTable 等、実際の HTTP ソケット情報 |
| 有効化・無効化 | 公式にサポートされた MSFT_NetAdapter Enable/Disable（固定 CIM/WMI メソッド）等の限定した API |

- OS アダプターは Sysacta.Windows/Network、ドメイン/型/テスト用インターフェースは Core、UI/構成ルートは App。既存 .NET 10 / TFM / win-x64 自己完結配布 / WSL cross-build を維持する。追加依存は必要最小限。
- Native 構造体のサイズ/アラインメント、配列の読み取り境界、可変長バッファの上限と再試行回数、SafeHandle/finally による確実な解放、IPv4/IPv6/スコープ、キャンセル不能な API を調査する。DLL は System32 等から安全に解決する。
- 変更には正式な API のみ。管理者起動が必要ならユーザーのローカル操作のみとし、MCP から昇格、特権の有効化、UAC プロンプト、資格情報の入力/保存、サービス/タスク作成を行わない。必要権限が不明なら拒否する。
- SetIfEntry 等の古い API や PnP デバイスの Enable/Disable と、インターフェースの管理状態を変更する API の違いを確認する。目的外のデバイス全体/ドライバー操作を代用しない。非公開 API・CLI フォールバックは不可。

## 2. ツール契約

| Tool | 引数 | 種別 | DefaultPolicy |
|---|---|---|---|
| network_get_status | なし | 読み取り | On |
| network_list_adapters | なし | 読み取り | On |
| network_get_traffic | adapter? | 読み取り | On |
| network_set_adapter_enabled | adapter, enabled | 状態変更 | Off |

- SysactaTool<TArgs,TData>、ToolCatalog、ToolExecutor、厳格な JSON Schema/outputSchema と既存の認可/監査/電源ゲートを利用する。既存 DB の追加ツールは無効で追加、既存クライアントへの自動付与なし。
- adapter はカテゴリ network の canonical ID または明示登録した別名のみ。省略可能なのは network_get_traffic のみ。変更では adapter 必須、all/default/空文字/null/複数指定を拒否する。enabled は厳格な boolean。
- 未知/余分な引数、型不正、過長、空白や予約語、不正 ID を拒否する。接続先 IP/ホスト/コマンド/インターフェース名・番号・経路の任意入力を受け付けない。
- 既定タイムアウト 5 秒。変更操作で正式 API が長時間を要する場合のみ上限を実測に基づき変更する（初期案 15 秒）。API の呼び出し回数、列挙/サンプルの件数、読み戻し時間を有限にする。

## 3. アダプター識別と UI

- canonical ID は公式の安定 InterfaceGuid をもとにした不透明な形式（例: net- + 32 桁小文字 hex）。現在のインターフェース番号/LUID/名前/MAC/IP は安定 ID の代替にしない。Guid が空・重複、相互変換や照合に失敗した場合、推定で ID を発行しない。
- InterfaceGuid と実行時の LUID/Index、必要な公式プロバイダーの InstanceID 等の一貫性を検証する。Index は IPv4/IPv6 で違う場合があることに注意。再起動・取り外し・再インストール・仮想 NIC の再生成で識別子が変わる場合は明記する。
- 物理、有線、Wi-Fi、ループバック、トンネル/VPN（Tailscale 等）、Hyper-V/WSL、仮想/不明の区分を公式の型/フラグ等で表す。名前や製造元の文字列だけで安全な物理 NIC と判断しない。識別不能は unknown。
- 管理状態（enabled/disabled/unknown）と稼働状態（up/down/dormant/not_present/lower_layer_down/unknown 等）、メディア接続状態を区別する。未接続を無効化済みと扱わない。無効化中のアダプターも正式 API で識別可能な場合は一覧に含め、再有効化に同じ ID を使えることを検証する。列挙に出なくなる場合は状態を捏造せず、再有効化経路を確立できない対象の無効化を禁止する。
- 既存 Devices ページに「ネットワーク」を追加し、状態・種別・リンク速度・別名を管理する。既存 device_aliases とカテゴリ内一意/予約語/衝突検査を利用し、MCP から登録/変更不可。切断/消失した ID は未接続として保持し、明示的再紐付け以外の自動フォールバックを行わない。
- UI の読み取りは既存 PageViewModel / 非同期処理・スクロール/リスト規約に従う。状態変更の汎用テストボタンを追加しない。ローカル復旧操作を設ける場合は既存 executor 経由で同じ安全性条件と明示確認を必要とし、危険な無効化を UI から迂回させない。Windows のネットワーク設定から復旧する方法を文書化する。

## 4. 読み取り契約

### network_list_adapters

- 物理/仮想を含め、取得できるアダプターを安定順序で返す。id、sanitized name、aliases、kind、admin_state、oper_state、media_state、送受信別 link_speed_bps、IPv4/IPv6 の有効なユニキャストアドレスと prefix_length（必要に応じ scope を区別）、管理変更の可否/固定理由を返す。
- アドレスの付与は OS 観測値であり、インターネット到達性ではない。MAC、SSID/BSSID、DNS サフィックス、Wi-Fi キー、接続履歴、詳細な PnP パス/ハードウェア識別子、ユーザー/PC 名は返さない。名前は長さと制御文字・パス/URI を検証する。
- 一覧の返却上限初期案 128、内部処理上限 512、アドレス/アダプター初期案 16（IPv4/IPv6 の切り詰めを明示）。正常な空、アクセス失敗、不明、切り詰め、部分失敗を区別し、count/truncated/failed_count 等を返す。上限超過時の一覧を完全と扱わない。

### network_get_status

- 現在の OS が報告する接続/アダプターの概要、稼働中の ID、IPv4/IPv6 のデフォルト経路の有無と対応アダプター ID 等を返す。複数経路を勝手に 1 件に絞らない。実際のインターネット通信経路や接続成功を断定しない。
- 既存 OS のネットワーク接続判定を利用する場合は、NCSI 等の OS 観測値として区別する。外部サイトへ HTTP/DNS/ping 等を送信しない。独自のインターネット到達性試験は提供しない。
- ルーティング表全体、相手側 IP、接続先/ポート一覧は公開しない。必要な経路情報の読み取りはガードの内部処理に限る。IP アドレスはネットワーク状態の正当な結果に限り返し、監査・診断ログに応答全文を残さない。
- 一部取得不能時は null と固定の reason、正常なゼロ/false と区別する。

### network_get_traffic

- adapter 指定時は ID/別名で解決した 1 件のみ。省略時は取得可能な各アダプターの個別結果を返す（all を変更操作に持ち込まない）。ループバック・トンネル・VPN・仮想を含むため、アダプターの通信量を単純合算して PC 全体の通信量と表示しない。
- 64 bit の OS 累積送受信 octets（byte）を利用し、累積値とサンプル区間の差分/速度を区別する。リンク速度と実トラフィックを混同しない。送信/受信の方向は PC 側。bit/s と byte/s の単位を明記する。
- 1 回の要求内で 2 回のサンプルを取り、単調時計（TimeProvider/Stopwatch）で測った実経過時間を使う。初期案 1 秒（固定、クライアントから任意測定期間を受け付けない）。rate_bps = delta_bytes × 8 / elapsed_seconds。整数オーバーフロー、JSON の 64 bit 値と JavaScript の精度限界に配慮し、採用型・丸めを契約に明記する。
- 2 サンプルは同じ canonical ID と同じ実行時同一性の対象を照合する。消失/追加/再接続・LUID/Index の変化、管理状態やリンク状態の遷移、カウンターの減少/リセット、サンプル不能、経過時間不正を検出した区間は速度を null と理由にする。無条件の wrap 補正や負値/ゼロへの丸めを行わない。観測できないリセット/遷移の限界も文書化する。
- カウンターが同値で正常な区間は実測 0。未対応・不明と区別する。最大 128 件/要求を初期案とし、対象固定・部分結果・切り詰めを明示する。タイマー・バックグラウンドキャッシュ・永続履歴を作らない。キャンセル可能な待機と実処理完了までの executor スロット保持を維持する。

## 5. network_set_adapter_enabled（危険操作）

### 対象・権限

- explicit adapter + boolean のみ。初期方針は管理者起動済みの場合だけ利用可能（採用する公式 API が通常権限で安全に動作する場合は根拠を示す）。権限不足なら capability unavailable と直接呼び出し拒否。MCP から昇格しない。変更ツールは既定 Off、危険性を description/UI に明記。
- 変更対象は正しく識別でき、同じ ID で有効化・無効化が可能と確認したローカル物理有線/Wi-Fi NIC に限定する。ループバック、VPN/トンネル/Tailscale、Hyper-V/WSL/ブリッジ/チーム/仮想スイッチ、共有/依存関係が不明、非対応のデバイスは初期対象外。物理 NIC であっても仮想ネットワークの下位経路になり得る。
- OS/プロバイダーの admin_state を読み戻して真の no-op を判定する。稼働状態 down を disabled と同一視しない。無効化対象が見つからない場合は成功を返さない。
- リソースロックは全ての管理状態変更で共有する固定キー network:topology と canonical ID（他の操作対象と必要な固定順序）。複数 NIC の同時無効化によって個別の安全判定が無効になることを防ぐ。独立した読み取りは既存 executor の方針を維持し、変更を挟んだトラフィック測定は状態不明とする（必要ならプロセス内の変更世代を用いる）。
- ロック取得後、対象の再解決と Guid/LUID/プロバイダー ID の再照合、管理状態・権限・経路の事前検証を完了し、BeginSideEffect の直後に対象を限定した正式メソッドを 1 回だけ呼ぶ。WMI/CIM の場合は固定名前空間/クラス/メソッド、列挙した対象インスタンスに対する操作のみ。任意クエリや入力値のコード連結を行わない。
- 別名は解決時の canonical ID に固定し、待機中に別名が再紐付けされても別 NIC に操作しない。OS が同じ Index を再利用しても別対象へ書き込まない。

### 通信経路保護（最重要）

リモート接続を切断して復旧不能になることを避けるため、利便性より fail-closed を優先する。現在の MCP リクエストの接続元だけでなく、他の接続・プロキシ・下位ネットワーク経路への影響を考慮する。

- 最初に、既存の Kestrel/RequestGuards/Caller と実ソケットの接続情報を確認する。必要な場合のみサーバー由来の信頼できる local/remote アドレス等を型付きで Core に伝える小さな拡張を行う。MCP 引数・Host/Origin・任意の Forwarded/X-Forwarded-For ヘッダーを経路証拠にしない。既存の認証/予算/監査/接続元の契約は変えない。新しい信頼プロキシ設定は作らない。
- 127.0.0.1 / ::1 の接続はローカルのクライアントと Tailscale Serve 等を区別できない。プロキシの実際の下位経路はソケットだけからは分からない。ループバックを安全の証拠にせず、経路が不明なら MCP 経由の無効化を拒否する。
- 保護対象: 現在および他の既知の MCP 接続/待受に対応する NIC、IPv4/IPv6 のデフォルト経路を持つ NIC、稼働中/メディア接続中の NIC、実際に使われるアドレス・経路を持つ NIC、VPN/トンネル/仮想 NIC およびその下位依存 NIC。ワイルドカード bind、複数経路・IPv6 scope/IPv4-mapped IPv6、NIC チーミング/ブリッジ、ルート変動を考慮する。
- 初期の無効化は、明確に未使用・未接続で IP/経路/依存関係がない物理 NIC、かつ現在の接続への影響がないと確認できる場合だけ許可する。情報が欠落・矛盾・切り詰め・検査エラー・プロキシ経路不明なら拒否。単なる低トラフィック、別 NIC が up、既定ルートではない、名前の一致、ループバック接続を十分な条件としない。
- 公式 API の情報だけでこの安全判定を実装・検証できないなら、MCP 経由の無効化は未対応として一律拒否してよい（有効化のみ実装する場合は仕様との差分を明示）。無効化を強制する force 引数や安全判定オフの設定は追加しない。既存のアクセス権限の許可は経路安全判定の代替にならない。
- 有効化も OS の経路・メトリック・VPN の状態を変える可能性がある。対象の同一性、正式 API の対応、管理権限、状態変化の可否を検証し、接続継続を保証しないことを説明する。明らかに通信に悪影響を与える構成や判定不能な特殊 NIC は拒否する。無効化の補償として自動的に再有効化/切断/ルート変更をしない。
- 経路チェックはロック内で副作用の直前に実施する。外部 OS/ドライバー/プロキシによる変更との競合を完全には排除できない。安全な証明がないものを verified にしない。判断の固定理由（active_adapter / route_in_use / dependency_unknown / connection_path_unknown / unsupported 等）を返す。IP や生の経路/相手側情報はエラーに含めない。

### 結果・復旧

- OS メソッドの戻り値/非同期ジョブの正式な契約を確認する。API 受理は accepted、同じ対象の管理状態を有限の読み戻しで確認した場合のみ verified。管理状態と link up/down は別項目とする。通信復旧を証明したとは扱わない。
- no-op は読み戻し済みの場合のみ verified。明確な事前拒否は error。開始後のタイムアウト/例外/不確定な API 結果は unknown、retryable=false。確認済みの不一致は適切な error/partial/unknown と固定理由を返し、無条件に再試行しない。非同期 API が完了前に戻るなら状態変更が続く間のロック保持を検証し、安全に扱えなければその API を不採用とする。
- 監査は pending を永続化してから変更し、失敗時は OS 操作なし。監査する引数は解決済み canonical ID と enabled の boolean のみ。結果に接続元やパス、生 WMI 例外を返さない。
- 変更は PowerTransitionGate の通常状態変更として admission を通す。非キャンセル可能な OS 呼び出しは応答タイムアウト後もロック・スロット・電源ゲートを実完了まで保持する。準備中のキャンセル/失効/全体無効は変更を行わない。
- 自動リトライ、切断後のタイマー復旧、独自の権限迂回、別 NIC へのフォールバックは実装しない。ローカル Windows 設定/デバイス管理の標準手段による復旧を案内し、実機で確認できない場合は記録する。

## 6. テスト要件

### Core / Infrastructure / MCP

- 4 ツールの厳格な schema、既定、新規/既存 DB の無効・未付与、未認可/失効/全体無効、未知引数/adapter 省略/予約語/型不正で OS 変更なし。別名の解決、ID 衝突・消失、再紐付け時の対象固定、カテゴリ分離。
- IPv4/IPv6、仮想/物理/不明、管理状態と稼働状態、無効 NIC の一覧、安定 ID/Index 再利用、null とゼロ、列挙上限・部分失敗。出力の単位と schema を固定する。
- 通信測定: 正常差分、実経過時間、ゼロ、64 bit 境界/オーバーフロー、減少/リセット、対象消失・新規追加・リンク変化・変更世代、サンプル失敗、キャンセル、上限、合算なし。TimeProvider とフェイクで時間/カウンターを決定的にする。
- 管理状態の正しい no-op、昇格不足・不明/非対応での拒否、正式 API 成功/失敗/タイムアウト、同じ ID の読み戻し、Index 再利用/消失、再接続と区別、開始後の unknown と再試行禁止。
- 経路ガード: IPv4/IPv6 の直接接続、loopback/IPv4-mapped IPv6、Tailscale Serve 相当のループバックプロキシ、不明な経路、複数デフォルト経路、アクティブな有線/Wi-Fi、VPN/トンネル/仮想/下位依存、ブリッジ/チーム、情報不足/途中失敗/切り詰め、判定可能な未使用 NIC。偽の転送ヘッダーで許可されない。MCP 無効化を一律未対応とする場合は全経路で OS 変更が 0 回であること。
- 同時に別 NIC を無効化しようとする要求の直列化と再検査、ロック待ち中の失効/無効化、pending 監査失敗、電源遷移との排他、キャンセル/タイムアウト後の遅延変更防止。ハング中のロック/スロット保持。テストの待ちには有限の上限を設ける。
- synthetic IP/MAC/SSID/パス/例外/転送ヘッダーを使い、監査 DB/WAL/CSV/JSON と診断ログへの不要な漏洩なし。ネットワーク状態の明示契約として返す IP と既存の監査接続元は例外。

### Windows / App / 実機

- Windows CI は構造体サイズ・公式 API の読み取り/列挙・カウンターサンプル、フェイクによる変更・安全性ガード、UI/スクロールと app smoke を確認する。**自動テストでは実 NIC の有効化/無効化、ネットワーク切断、ルート/DNS/FW/プロキシ変更を一切行わない。**
- 実機読み取りは通常権限で実施し、Windows のネットワーク設定・タスクマネージャーまたは読み取り専用の標準コマンドの値と比較する。実在の有線、Wi-Fi、VPN/仮想 NIC、IPv4/IPv6、無効 NIC が利用可能なら照合。通信カウンター・速度・リンク速度の差は測定窓の違いを考慮する。試験のための外部通信や高負荷通信を発生させない。
- 変更の実機確認は、利用者が対象 ID・操作・管理者起動を個別に明示承認し、PC に直接アクセスでき、独立した通信経路と復旧手段がある場合のみ。未使用の予備物理 NIC を対象にし、MCP 経路・Tailscale・既定経路・稼働中 NIC の無効化は実施しない。変更前状態を記録し、利用者の管理下で復元する。承認/安全な予備 NIC がなければ実機変更は未確認とする。
- 危険な対象の拒否はフェイク、または明示承認済みの副作用のないガード確認で検証する。実際に切断を発生させて復旧を試験しない。実機の遠隔接続上では変更を試さない。
- Release build/test、Windows CI、自己完結 publish、app smoke を実施。Windows 実機の差異・未対応 NIC・権限条件・復旧手段の確認範囲を明記する。
