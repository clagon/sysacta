# Sysacta — Phase 1C-2: ディスプレイのモード・電源・入力切替

## 目的と範囲

spec §7.2 / §8 / §9 / §10 / §12 に従い、Phase 1C-1 のディスプレイ基盤に display_set_mode / display_set_power / display_set_input を追加する。画面消失・操作不能・誤対象への書き込みを重点的に防ぐ。技術的に安全な実装方法が確立できない機能は未対応として報告する。

最初に README.md、AGENTS.md、docs/spec.md、docs/tools.md、docs/security.md、docs/phase-1c-1.md、docs/phase-1c-1-progress.md、docs/phase-1b-exp-progress.md、docs/manual-tests.md、現行コードとテストを読む。最新 main を基点とする専用ブランチ（例: phase-1c-2）で作業し、独立した PR を作成する。自動マージしない。

Phase 0〜1C-1 の認証・認可・監査容量・要求予算・排他・副作用開始点・部分結果・対象識別を維持する。Phase 1D 以降、既存オーディオの別課題、管理 UI 全体の再設計には着手しない。

## 1. 技術調査と採否

公式 Microsoft 文書、実際の API 契約、必要に応じ MCCS の仕様や既存 OSS の実績を確認し、参照 URL・バージョン/コミット・ライセンス・Windows 11 x64 での対応・権限・制約・未確認事項を docs/phase-1c-2-progress.md に記録する。

| 用途 | 調査候補 |
|---|---|
| 表示モードの検証・適用 | ChangeDisplaySettingsExW / CDS_TEST、必要なら SetDisplayConfig の検証/適用 |
| 現在の設定の再取得 | EnumDisplaySettingsExW / QueryDisplayConfig |
| DDC/CI 能力文字列 | GetCapabilitiesStringLength / CapabilitiesRequestAndCapabilitiesReply |
| 電源・入力状態の読み取り | GetVCPFeatureAndVCPFeatureReply |
| 電源・入力の変更 | SetVCPFeature（許可した機能・値のみに限定） |

- モード変更では、対象表示ソースのみの適用、現在トポロジーの維持、永続化の有無、失敗時の状態、戻り値、ドライバ依存性を確認する。全デバイスを対象とする適用フラグや意図しない他画面への変更を避ける。
- DDC/CI の低レベル API は電源（MCCS VCP 0xD6）と入力（0x60）のみを、仕様・機器の能力・読み取りによる根拠の範囲で使用する。任意 VCP コード・任意数値・生の能力文字列に基づく無制限操作を公開しない。
- 能力文字列が不正確・欠落・不正形式でも、対応値を推測しない。問い合わせ失敗と明確な非対応を区別する。メーカー固有値や HDMI/DP の対応関係を一般化しない。
- P/Invoke の ABI、文字コード、構造体、配列長、エラー、ハンドル解放を公式定義と照合する。能力文字列の取得長、パース深さ・要素数を有限にする。
- 公式 API を優先する。非公開 API が必要と判明した場合は今回の通常実装に混ぜず、別途 Experimental の採否を報告する。外部 CLI、GUI 自動化、レジストリ直接変更、ドライバ追加、権限昇格は禁止する。
- 状態変更を伴う能力検出は禁止する。GetAvailability は安価・副作用なし・長時間の同期問い合わせなし。

## 2. 公開ツール・引数

| ツール | 必須引数 | DefaultPolicy | 種別 |
|---|---|---|---|
| display_set_mode | device, mode_id | Off | 状態変更 |
| display_set_power | device, state | Off | 状態変更 |
| display_set_input | device, input_id | Off | 状態変更 |

すべて初回導入・アップグレードともに無効。既存クライアントへの自動付与なし。サーバー全体とクライアント別許可の積集合を維持する。ユーザーがローカル設定で明示的に許可する。通常の MCP 呼び出しに対する毎回の対話確認は要求しない（spec の合意を維持）。

- device は一意な正規 ID または登録済み別名。省略・明示 null・all・default・曖昧な名前・未知 ID を拒否する。
- mode_id / input_id は当該対象について列挙された識別子のみ。厳格な型・長さ・制御文字・未知引数の検証を既存スキーマ基盤で行う。任意の解像度、周波数、入力番号、VCP 生値を指定する代替引数を追加しない。
- state はまず on / off のみ。MCCS の standby / suspend 等は根拠と必要性が明確になるまで公開しない。off は物理的な電源断を保証する意味ではなく、機器が対応する省電力状態への要求とする。電源コードの具体的な対応は調査で確定する。
- タイムアウトは通常 5 秒、DDC/CI 10 秒を初期案とし、適用・読み戻しの実測により根拠付きで調整する。ネイティブ処理のタイムアウト後の隔離は維持する。

## 3. 表示モード変更

### 対象と事前検証

- Phase 1C-1 の DisplayListModesTool.ModeId、DisplayMode、DisplayTarget を再利用する。既存 mode_id の契約を壊さない。
- 解決時に正規の物理対象と表示ソースを特定し、ロック取得後にも照合する。複製表示、仮想表示、曖昧な対象、識別不能なトポロジー、複数物理モニターを共有するソースは拒否する。
- ロックとアダプターのゲートを取得後、現行の列挙結果から mode_id を再照合し、同じディスプレイの一意なモードであることを確認する。切り詰めや OS の列挙制約を考慮し、未列挙の値を合成しない。
- EnumDisplaySettingsEx の整数 Hz と DisplayConfig の分数 Hz は区別する。既存モード ID が区別できない信号モードを勝手に選択しない。ビット深度・インターレース・回転・固定出力等の属性の意味も維持する。
- 現在モードと、復旧に必要な表示構成を取得する。既に要求モードに一致すれば no-op / verified。
- CDS_TEST 等、実際に表示状態を変更しない検証 API がある場合に実施し、成功しない場合は変更しない。検証成功は実際に表示できることの保証ではない。
- 検証後・書き込み前にソースと対象 ID の対応が変わっていないか確認する。OS の内部構造体をクライアント入力から直接組み立てない。

### 適用・結果

- 初期方針はセッション内の非永続変更（レジストリへの保存を要求しない）とする。OS の実挙動を調査して文書化し、非永続性が保証できなければその旨を明示する。永続化の追加は別途判断する。
- 対象表示以外の解像度・配置・回転・プライマリ・有効/無効状態・接続設定を意図して変更しない。
- API の戻り値を分類し、再起動要求や失敗を成功にしない。現在の設定とトポロジーを再取得し、要求モードとの一致を確認する。
- 他の表示への予期しない影響が観測された場合は、結果に明示し、追加の変更を中止する。観測された変化を全て Sysacta によるものと断定しない。
- 結果は device_id、要求 mode_id、変更前後の確認済みモード、changed、復旧手段の有無、必要なエラーを含める。verified は確認した設定値の一致であり、利用者に実際に画面が見えていることを保証しない。

## 4. 画面消失時の復旧設計

spec は毎回の実行確認なしと、実現可能なローカル復旧手段を要求している。この両方を維持する。MCP 側の追加確認やリモートの復旧用任意コマンドを作らない。

- モード変更前の復旧情報を、対象 ID・元のモード・必要なトポロジー・適用予定モードとともに保存する。復旧情報を作成できない場合はモード変更を拒否する。
- ローカル管理コンソールから直近の変更を復旧できる最小限の操作を設ける。画面が見えない場合にも利用できる安全なローカル手段（例: ユーザーが設定する復旧ホットキー）を検討する。利用可能性、キー競合、アプリ停止時の限界を明記する。
- 復旧はローカル利用者が明示的に発動する、元の設定への限定的な操作とする。任意モード・任意対象の変更 API に転用しない。元の表示が別の機器に置き換わった場合は拒否する。外部操作や後続の変更で状態が変わった場合にも古い復旧情報を無条件に適用しない。
- 復旧情報は成功・失敗・不確実な結果に対応させ、必要最小限の保持期間・件数にする。再起動後に有効と主張する場合は、永続化・検証・誤適用防止を実装してテストする。今回の初期案はアプリ稼働中の直近 1 件の復旧情報。復旧操作も排他と監査を利用する。
- 自動タイマーによる無条件ロールバックは初期実装に含めない。導入する場合はユーザーのローカル設定・認可失効後の動作・新規操作との競合・監査・キャンセルの責務を別途設計し、承認を得る。
- 復旧経路を安全に確立できない場合は、対応範囲を制限するか未対応として報告する。特に唯一のアクティブ画面での変更は、利用可能な復旧手段がない限り拒否する方針を初期案とする。
- 電源 OFF や入力切替では、DDC/CI 自体が応答不能になることがある。OSD・物理電源ボタン・別入力・別画面等の外部復旧手段が必要な場合を明示し、Sysacta から必ず復帰できると保証しない。

## 5. DDC/CI の電源・入力切替

### 共通制約

- Phase 1C-1 の物理対象識別・ハンドル寿命・同一ゲート・PrepareWrite パターンを再利用する。論理表示名や物理ハンドル列挙順で対象を推測しない。
- VCP は目的に対応する固定のコードと、調査で確認した許可値に限る。ハードウェアへの書き込みを伴う能力照会、未知機種の試行書き込みは禁止。
- 取得した能力・現在値・対象機器を確認してから書き込みを準備する。対象や値が不明な場合は変更しない。内蔵/仮想/曖昧な対象に DDC/CI を代替適用しない。
- API が成功しても、スリープや入力切替で同じ通信経路が使えなくなる可能性がある。確認できた値は verified、OS/API が受理したことのみ確実なら accepted、受理や副作用が不明なら unknown。accepted と実際の表示状態を混同しない。
- 失敗した書き込みを自動再試行しない。画面や通信が消失したこと自体を要求成功の証拠にしない。結果不明を未実行として扱わない。
- 電源/入力切替の後は必要な能力情報を再評価する。復帰不能な機器・接続での制約をツール説明と UI に記載する。

### display_set_power

- state=on/off は調査で根拠を得た VCP 値にのみ変換する。off はハードオフや強制的な電源切断ではない。
- 現在の状態を取得し、既に目標に一致する場合は no-op。未知状態から推測で操作しない。
- on で復帰させるには、対象が正規 ID で解決でき、通信経路が利用可能であることが必要。消失した機器や以前のハンドルに対して書き込まない。
- 全画面に影響するシステムのモニター電源メッセージ、PC のスリープやシャットダウンを代替に使わない。
- 最後の画面を OFF にする場合は、ローカルでの物理復旧が可能であることを利用者が認識した上で許可する。毎回の確認を追加するのではなく、必要に応じローカル許可時の明確な注意・制約を設ける。

### display_set_input

- 機器が報告する対応入力の中から、意味と安全性を確認できた値だけを公開する。現在値が読み取れることと候補入力への切替が可能であることを区別する。
- input_id は正規デバイス ID と入力の正規情報に結び付いた決定的な不透明 ID とする。別の機器で発行された ID や、再列挙で見つからない ID は拒否する。
- 入力候補の表示名は、仕様で確認した意味の範囲で付与する。物理ポートの HDMI 1/2 等と一対一に対応する根拠がない場合は断定しない。
- 現在入力と指定入力の対応・候補をロック取得後に再照合する。別の入力へのフォールバックや順次切替による探索を行わない。
- 現在入力を取得し、既に一致する場合は no-op。変更後の read-back が不能な場合は accepted / unknown を適切に使う。
- 別入力から戻せない場合があること、入力切替は信号の存在を保証しないことを説明する。

## 6. 読み取り契約・能力情報

新規の汎用 VCP ツールは作らない。既存 display_get_state に、電源・入力の状態と操作候補を取得するための加算的な拡張を行う。

- 初期案: optional bool include_switching（既定 false）。true の場合にのみ電源・入力の能力・現在状態・利用可能 input_id 一覧を問い合わせる。既存の引数なし/対象指定呼び出しに追加の遅い DDC/CI 通信を強制しない。
- 結果は support（supported / not_supported / unavailable / unchecked）、取得可能な現在 state / current_input_id、inputs（input_id、表示名）、error_code 等を型付きで返す。未確認や失敗時は null/空一覧の理由を明示する。候補数と文字列長に上限を設ける。
- 既存 JSON の意味・既定挙動を変更しない。新規項目の省略時の扱いと実際の outputSchema を文書化し、互換性テストを追加する。必要ならタイムアウト設計を見直すが、基本読み取りに不必要な長時間処理を追加しない。
- display_list_devices は引き続き軽量なトポロジー列挙とする。能力未確認の機器を対応済みとして表示しない。管理画面の情報は確認できた事実だけを表示する。

## 7. 排他・認可・監査

- 既存 ToolCatalog / ToolExecutor / SysactaTool<TArgs,TData> を利用する。別経路のリモート OS 操作を作らない。ローカル復旧にも明確な実行・監査境界を設ける。
- 全ディスプレイ変更で display:device:{id} を共有する。モード変更は表示トポロジー全体や他モニターの状態に影響し得るため、既存の DDC/CI/WMI ゲートと同じ調停に組み込む。モード変更と既存の輝度/コントラスト、電源/入力切替が競合しないことをテストする。
- 全体トポロジーを読む検証同士が Sysacta 自身の別変更を誤検出しないようにする。保守的な全ディスプレイ変更の直列化は許容する。ロック取得順を固定し、読み取り経路・UI・復旧が逆順に取得しないようにする。
- 時間のかかる問い合わせ、対象再検証、モードの CDS_TEST、WMI/DDC/CI の準備を最終認可より前に完了する。PrepareWrite と同様に、実際の最初の OS 書き込み直前で BeginSideEffect を呼ぶ。複数の書き込みが必要な場合のみ BeginNextSideEffect を利用し、キャンセル・失効後に新たな書き込みをしない。
- 監査 pending が永続化できない場合は副作用を拒否する。ロックとハンドルは実処理・読み戻しの終了まで保持する。非キャンセル可能なネイティブ処理はタイムアウト後も隔離する。
- 結果の progress / partial / unknown / error を既存共通基盤で返す。読み戻し不能・意図しない変化・後続の失敗を隠さない。新しい未検証の共通基盤を並行して作らない。
- 監査は安全な enum と解決済み正規 target のみ。mode_id / input_id の生のユーザー入力、能力文字列、デバイスパス、結果全文、例外全文を保存しない。必要な追加監査項目は既存の安全な形式を維持する。SEC-01/03/05/06 の回帰テストを維持する。

## 8. テスト・実機検証

### 自動テスト

- 3 ツールの既定無効、新規/既存 DB、既存トークンへの自動付与なし、直接呼び出し拒否、厳格な JSON Schema、all/省略/不正 state/他機器の ID の拒否。
- 同一名・同型番・複製・複数物理ハンドル・トポロジー変更・ホットプラグ・切断・対象再解決と曖昧性拒否。
- モードの no-op、最新列挙との照合、検証失敗・再起動要求・適用失敗、読み戻し不一致、他画面への影響、復旧情報取得不能、唯一の画面で復旧不能な場合の拒否。
- 復旧情報の生成・寿命・対象変更・後続設定変更・古い記録の拒否・安全な限定復旧・監査・排他。ホットキーを採用した場合は競合と登録解除をテストする。
- 能力文字列の不正形式・上限・未対応・曖昧な入力・メーカー固有値、DDC/CI の現在値取得不能、on/off の許可値、input_id の一意性と再照合。
- 電源/入力切替直後の通信消失、API 受理と実行完了の区別、結果不明、no-op、失敗後の無再試行、書き込み回数。
- 準備中の失効・権限剥奪・再発行・期限切れ・全体無効・キャンセル・タイムアウト・監査容量不足で実書き込みゼロ。
- 既存ディスプレイ変更との排他、ゲート待ち中のキャンセル、モード変更中の DDC/CI ハンドルの寿命、ハング時のロック・スロット維持。ネイティブ呼び出しが返らない場合をフェイクで検証。
- 新規の読み取り項目の互換性・スキーマ・MCP isError・監査結果・機密情報非記録・管理 UI の表示。
- 既存すべての回帰テストと Windows CI / アプリスモークテストを維持する。

### 実機

- 通常 CI ではディスプレイのモード・電源・入力を実際に変更しない。ネイティブ宣言のサイズ、読み取り、フェイクによる結果契約を検証する。
- 実機の読み取りのみで能力、現在モード・電源・入力、対応候補、応答時間を調査し、機種/接続/Windows ビルドごとに記録する。モニターに書き込まずに分からない事項は未検証とする。
- 実際のモード・電源・入力変更は、SYSACTA_HARDWARE_TESTS=1 だけで実行しない。利用者が対象モニター・具体的な変更内容・復旧手段を明示承認した場合に限る。自動実行や全画面変更は禁止する。
- モード変更は安全に復旧できる副画面等から、既知の正常な元設定と復旧手段を用意して確認する。入力切替では実際に接続された信号と OSD で戻せること、電源変更では物理復帰が可能なことを事前に確認する。承認なし・必要条件を満たさない場合はスキップする。
- テストの復元操作は製品の無断ロールバックとは別。復元失敗を隠さない。結果は承認された実機試験の範囲に限定し、未検証機種への一般化を行わない。
- 実機での書き込みが未検証なら明記し、動作保証済みと案内しない。実用可能性が確認できない場合は公開範囲を制限する。
